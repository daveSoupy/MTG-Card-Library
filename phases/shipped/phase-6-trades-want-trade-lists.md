# Phase 6 — Trades & Want/Trade Lists

(Assumes Phases 1–4 are complete. References the Trades, Want List, and Trade List entities in `CLAUDE.md`.)

- **Record a trade**: pick a counterparty (free-text name/contact note), add cards going out (from the Collection — choose which copies/location) and cards coming in (new cards, assigned to a Storage Location on completion), with an optional date and notes.
- **Draft vs. completed status**: a trade can be built and edited freely while in "draft" without touching the Collection. Only marking it "completed" applies the changes — this keeps your collection numbers accurate while a trade is still being negotiated.
- **On completion**:
  - Outgoing cards: decrement Collection quantity at the chosen location. If a card being traded away is currently allocated to a deck, flag the conflict so you can resolve it (unassign from the deck, or offer different copies) before finalizing.
  - Incoming cards: increment Collection quantity at the chosen location (default to an "unsorted" location if not specified yet); check against the Want List and offer to mark any matching entries as fulfilled.
  - **Reconcile the Trade List:** if a completed trade drops a card's owned quantity below what's currently flagged as "available to trade" on the Trade List, clamp that Trade List quantity down to match (it can never claim more copies as tradeable than you actually own) and surface a quick notice so it's not a silent change.
- **Trade history**: a running log of completed trades (date, counterparty, cards in/out) so you can look back at what you traded with whom and when.
- **Want List**: cards you're looking for, each with optional notes (target price, priority, specific set/printing) and an optional **linked deck** reference — when an entry was pushed from a deck's shopping list, it remembers which deck(s) needed it and shows a persistent "needed for: Deck A ×2" field in the list view (not just a tooltip), regardless of which named list the card sits in. If the same card is needed by multiple decks, consolidate into one row summing the quantity, listing each deck's need. Flag matches visually when browsing the Card Database or when adding "incoming" cards to a new trade.
- **Multiple named Want Lists**: support creating, renaming, and deleting any number of separate Want Lists (e.g., "Commander wants," "Budget upgrades," "Grails") — a card can be added to whichever list(s) make sense. Each named list has its **own independent custom order**: manually drag-to-reorder entries within that list to rank priority however fits that list's purpose. The deck-linkage field and consolidation described above apply within every list the same way.
- **Price alerts**: when a Want List entry has a target price set, check it during each price sync and flag (or notify) when the card's current market price drops to or below that target — turns the target-price field from a note into something the app actually acts on.
- When a Want List entry linked to a deck gets fulfilled (via a completed trade, or by editing the Collection directly), automatically re-check that deck's allocation and clear the entry if it's no longer needed.
- **Trade List**: mark specific owned copies (with quantity) as available to trade — browsable on its own, and exportable as plaintext (same convention as deck export) for pasting into a trade forum post or sharing with a trading partner. Note if a listed copy is currently allocated to a deck, same as the trade-conflict flag above. Reuses the same named-list-with-custom-order mechanism as the Want List if you want to split it up too (e.g., a "bulk trade" list vs. a "high-value trade" list).
