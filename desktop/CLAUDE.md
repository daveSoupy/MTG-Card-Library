# desktop/ — rules for the Electron shell

Auto-loaded for any session that touches this workspace. The design is `phases/apps/phase-32-desktop-app.md`; this is only what must stay true.

- **No renderer code, no Electron branches in `web/src`.** The window loads `http://127.0.0.1:<port>/` and the web client renders as in a browser. The only markup here is the status page inline in `main.ts` (a title, a line, the server's boot messages). If you find yourself copying a component, a type or a rule into `desktop/`, stop and undo it.
- **The server is `server/dist/index.js`, unmodified, on a bundled official Node** (`scripts/fetch-node.mjs`, version pinned in `package.json` → `config.nodeVersion`, checked against the root `engines.node`). Never `ELECTRON_RUN_AS_NODE`, never `@electron/rebuild`, `npmRebuild: false` stays. The prebuilt `better-sqlite3` for stock Node is what ships; a rebuild is the one way to lose FTS5. `scripts/check-packaged.mjs` runs `server/scripts/check-sqlite.mjs` with the *packaged* Node against the *packaged* binary after every build and fails the package if it fails. Keep that gate even though it has nothing to catch.
- **The shell owns exactly these environment variables:** `MTG_DATA_DIR` (`<userData>/library`, unless already set — a developer's override wins), `MTG_HOST` (`127.0.0.1`, or `0.0.0.0` while *Allow other devices on this network* is on), `MTG_PORT` (remembered in `<userData>/desktop-config.json`; stable across launches so phone bookmarks survive), `MTG_LOG_LEVEL` (`info`, to `<userData>/logs/server.log`, rotated), and `MTG_SHUTDOWN_ON_STDIN_CLOSE=1`. `server/src/config.ts` keeps `0.0.0.0` and `~/.local/share` as *its* defaults — right behind Tailscale and under systemd, wrong for a laptop on café wifi — and the shell overrides them because it knows its context. Do not change the server's defaults to suit the app.
- **Close hides, Quit stops — on every platform.** ⌘Q or the tray's Quit is the only thing that stops the server. Quit is SIGTERM and a wait (POSIX), or closing the child's stdin (Windows has no SIGTERM); SIGKILL only after `STOP_GRACE_MS`. Never kill first.
- **"Free port" means nothing answers on loopback.** `config.ts`'s probe binds *and* connects, because a `127.0.0.1` bind succeeds on macOS while another process holds `*:port` and then shadows it. The window always uses `127.0.0.1`, whatever `MTG_HOST` is.
- **Packaged layout** (`electron-builder.yml`): the shell in `app.asar`; the staged server tree as `extraResources` at `Resources/mtg-library/` (never in an asar — the `.node` binary and the sync `Worker` cannot load from one; never named `app` — Electron would load that directory as the application); the bundled Node at `Resources/node/`. `node_modules` is its own `extraResources` entry because electron-builder's copy filter silently drops a root-level `node_modules` from any source. `files` is the shell only — never point it at the workspace.
- **Staging (`scripts/stage.mjs`) mirrors the Dockerfile's runtime stage**: a fresh `npm ci --workspace=server --omit=dev` in a scratch directory, the `@mtg-library` workspace symlinks removed, `server/dist`, `web/dist`, `schema.sql`, `check-sqlite.mjs`. One `prebuild-install` per target swaps in that platform's `better_sqlite3.node`; the Windows build is produced on a Mac this way. `vendor/`, `staging/`, `out/` are never committed.
- **Targets are macOS arm64 and Windows x64.** No Intel Mac, no universal build, no Linux packaging — decided, not deferred.
- **Verification without clicking:** `MTG_DESKTOP_INSPECT=1` exposes the tray's actions on `globalThis.__mtgDesktop` for `electron --inspect`; `scripts/verify-lifecycle.mjs` drives the doc's items 4–6 through it, against the dev app or (`--app`) a packaged one. `MTG_DESKTOP_USER_DATA` points a run at a scratch userData. Neither is set by a packaged GUI launch.
