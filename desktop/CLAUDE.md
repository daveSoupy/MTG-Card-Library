# desktop/ — rules for the Electron shell

Auto-loaded for any session that touches this workspace. The design is `phases/apps/phase-32-desktop-app.md`; this is only what must stay true.

- **No renderer code, no Electron branches in `web/src`.** The window loads `http://127.0.0.1:<port>/` and the web client renders as in a browser. The only markup here is the status page inline in `main.ts` (a title, a line, the server's boot messages). If you find yourself copying a component, a type or a rule into `desktop/`, stop and undo it.
- **The server is `server/dist/index.js`, unmodified, on a bundled official Node** (`scripts/fetch-node.mjs`, version pinned in `package.json` → `config.nodeVersion`, checked against the root `engines.node`). Never `ELECTRON_RUN_AS_NODE`, never `@electron/rebuild`, `npmRebuild: false` stays. The prebuilt `better-sqlite3` for stock Node is what ships; a rebuild is the one way to lose FTS5. `scripts/check-packaged.mjs` runs `server/scripts/check-sqlite.mjs` with the *packaged* Node against the *packaged* binary after every build and fails the package if it fails. Keep that gate even though it has nothing to catch.
- **The shell owns exactly these environment variables:** `MTG_DATA_DIR` (`<userData>/library`, unless already set — a developer's override wins), `MTG_HOST` (`127.0.0.1`, or `0.0.0.0` while *Allow other devices on this network* is on), `MTG_PORT` (remembered in `<userData>/desktop-config.json`; stable across launches so phone bookmarks survive), `MTG_LOG_LEVEL` (`info`, to `<userData>/logs/server.log`, rotated), `MTG_ADVERTISE` (`1` exactly when sharing is on — Phase 33's mDNS advertisement; the server refuses to advertise a loopback bind anyway), and `MTG_SHUTDOWN_ON_STDIN_CLOSE=1`. `server/src/config.ts` keeps `0.0.0.0` and `~/.local/share` as *its* defaults — right behind Tailscale and under systemd, wrong for a laptop on café wifi — and the shell overrides them because it knows its context. Do not change the server's defaults to suit the app.
- **The pairing panel is the web app's.** *Pair a phone…* in the tray only loads `http://127.0.0.1:<port>/data#pair`; the QR, the address list and the wording live in `web/src/components/PairPhonePanel.tsx`. No QR code in the shell.
- **Close hides, Quit stops — on every platform.** ⌘Q or the tray's Quit is the only thing that stops the server. Quit is SIGTERM and a wait (POSIX), or closing the child's stdin (Windows has no SIGTERM); SIGKILL only after `STOP_GRACE_MS`. Never kill first.
- **"Free port" means nothing answers on loopback.** `config.ts`'s probe binds *and* connects, because a `127.0.0.1` bind succeeds on macOS while another process holds `*:port` and then shadows it. The window always uses `127.0.0.1`, whatever `MTG_HOST` is.
- **Packaged layout** (`electron-builder.yml`): the shell in `app.asar`; the staged server tree as `extraResources` at `Resources/mtg-library/` (never in an asar — the `.node` binary and the sync `Worker` cannot load from one; never named `app` — Electron would load that directory as the application); the bundled Node at `Resources/node/`. `node_modules` is its own `extraResources` entry because electron-builder's copy filter silently drops a root-level `node_modules` from any source. `files` is the shell only — never point it at the workspace.
- **Staging (`scripts/stage.mjs`) mirrors the Dockerfile's runtime stage**: a fresh `npm ci --workspace=server --omit=dev` in a scratch directory, the `@mtg-library` workspace symlinks removed, `server/dist`, `web/dist`, `schema.sql`, `check-sqlite.mjs`. One `prebuild-install` per target swaps in that platform's `better_sqlite3.node`; the Windows build is produced on a Mac this way. `vendor/`, `staging/`, `out/` are never committed.
- **Targets are macOS arm64 and Windows x64.** No Intel Mac, no universal build, no Linux packaging — decided, not deferred.
- **Verification without clicking:** `MTG_DESKTOP_INSPECT=1` exposes the tray's actions on `globalThis.__mtgDesktop` for `electron --inspect`; `scripts/verify-lifecycle.mjs` drives the doc's items 4–6 through it, against the dev app or (`--app`) a packaged one. `MTG_DESKTOP_USER_DATA` points a run at a scratch userData. Neither is set by a packaged GUI launch.

## Signing, notarisation and updates (Phase 34)

- **The environment decides; the config never names a certificate.** A *Developer ID Application* identity in the login keychain (or `CSC_LINK` + `CSC_KEY_PASSWORD` on CI) signs the Mac build; `APPLE_ID` + `APPLE_APP_SPECIFIC_PASSWORD` + `APPLE_TEAM_ID` notarise and staple it; `WIN_CSC_LINK` + `WIN_CSC_KEY_PASSWORD` sign the Windows installer. Absent, each step is a logged skip — a Mac with no certificate still packages for itself. The release workflow (`.github/workflows/desktop.yml`) passes `--require-signed --require-notarized`, so there a skip is a failure. Nothing secret is ever in a file in this repository.
- **Hardened runtime with the entitlements in `build/`.** `entitlements.mac.plist` is the app's, `entitlements.mac.inherit.plist` everything else's — the bundled Node and `better_sqlite3.node` included. Both carry `allow-jit`, `allow-unsigned-executable-memory` and `disable-library-validation` (Node's own official binary ships with the same three). Without `allow-jit` on the inherit file the first search is a crash; `check-packaged.mjs` reads the entitlements back off the packaged Node so that is caught locally, not by notarisation.
- **Only Mach-O files may be signed** — `mac.signIgnore` spares everything under `Resources/mtg-library/` except `.node`. `@electron/osx-sign` signs any file whose *content* looks binary (the web client's PNGs, a `.jpg` in some package's tests); codesign stores a non-Mach-O file's signature as an extended attribute, and the outer bundle then refuses to seal `Resources/` over it. The one Mach-O in the staged tree is `better_sqlite3.node`. If a second native module ever ships, extend the pattern, don't drop it.
- **Build output must not live inside a synced folder.** iCloud's Desktop & Documents sync (any File Provider) re-stamps every `.app` with `com.apple.FinderInfo` seconds after it is cleared, and codesign refuses a bundle carrying it. `package.mjs` detects a File Provider ancestor and makes `out/` a symlink into `~/Library/Caches/mtg-library-desktop/out`; every script keeps using `desktop/out`. The `afterPack` hook clears the attributes Electron's extracted zip arrives with. A `.nosync` suffix does *not* stop the stamping — tested.
- **electron-builder 26's layout is flat**: `hardenedRuntime`, `entitlements`, `entitlementsInherit`, `binaries`, `signIgnore` are keys under `mac`; `mac.sign` is a custom sign *function* there, not an options object. The phase doc's `mac.sign` block is from a v27 that had not shipped at build time.
- **Artifact names carry no spaces** (`MTG-Library-<version>-mac-arm64.dmg`): GitHub rewrites a space to a dot and electron-updater to a hyphen, and the two would never meet.
- **Updates (`src/updates.ts`): check on launch and daily, download in the background, apply on quit. Never a dialog the user did not ask for.** The tray gains *Restart to update to X* when one is staged; *Check for updates…* is the one dialog, because the user clicked it. `publish` in `electron-builder.yml` is where the installed app looks (it becomes `Resources/app-update.yml`); the release must carry the `.zip` and `latest-mac.yml` / `latest.yml`, which the workflow uploads with `gh` after the gate — never electron-builder's own publisher, so nothing reaches the release page that did not pass. `updateState.ts` is the Electron-free half (state, wording), unit-tested.
- **Quit goes through `app.quit()`, never `app.exit()`.** `shutdown()` stops the server first, then `app.quit()`; `quitting` makes `before-quit` and the window's `close` let it through. Electron's `quit` event is where electron-updater runs the NSIS installer on Windows, and `app.exit()` skips it. On macOS Squirrel's ShipIt swaps the bundle after the process exits either way, but the same path serves both.
- **The version is `desktop/package.json`'s, and the tag must equal it.** The running app compares that against `latest*.yml`; the workflow's first job fails fast on a mismatch. Cutting a release is `npm version X --workspace=desktop --no-git-tag-version`, commit, `git tag vX`, push the tag.
- **The shell does no migration.** A new build over an old data directory is `migrations.ts` on the next open, as under systemd and Docker.
